## 2026-10-27 - External URL Scheme Validation Across Runtimes
**Vulnerability:** `openExternalUrl` handed arbitrary URL schemes directly to `@tauri-apps/plugin-shell`'s `open()` on desktop or `window.open` in a browser. While Android's backend (`launcher_open_url`) restricted schemes via Rust, desktop Tauri configured `"shell": { "open": true }` in `tauri.conf.json` without regex scoping, allowing malicious or unexpected schemes (e.g., `javascript:`, `data:`, `file:`, `intent:`) to be dispatched to the OS or executed in browser tabs.
**Learning:** Shared frontend abstraction seams that dispatch external resources across platforms must enforce least-privilege scheme validation at the frontend boundary before handing off to platform openers, rather than assuming each target runtime restricts protocols equally.
**Prevention:** Always validate URL schemes against an explicit allowlist (`https://`, `http://`, `mailto:`, `tel:`, and approved deep links like `cybermanju://`) before delegating to `window.open`, `plugin-shell`, or native bridges.
